# DB03 S24 — bank-return private documentary evidence and independent exact-byte review

**30 October 2026 · inactive draft stacked on S23 #185.**

## Purpose and financial boundary

S22 reports an official `ADM-` payment return, stores immutable compensating reversals and freezes any applicant with a reported return; S23 has an independent Finance *ledger* review. Neither stage is proof of an actual bank settlement. S24 implements the next narrower **documentary evidence** step: a previously authenticated S22 return reporter securely uploads one immutable bank-return document into a private archive; a separately authorized Finance reviewer reopens the **exact stored bytes**, checks the recorded SHA-256/content type/length, and makes an accountable documentary decision. No external bank API/verified-settlement feed is currently connected. Consequently **no outcome treats the private document as an authoritative bank settlement, refunds money, restores allocations, or issues positive Finance clearance**.

## Protected evidence source

- Two new FORCE-RLS private append-only sources `finance_admission_bank_return_evidence` and `finance_admission_bank_return_evidence_reviews`; each real S22 return may have at most one source and one review in this version. Files are referenced by hard `file_objects` foreign keys, exact school/campus/return IDs, private evidence kind and immutable SHA-256 digest. The file must be `AVAILABLE`, `PRIVATE`, bound to the reporter, purpose `ADMISSION_BANK_RETURN_EVIDENCE` and supported PDF/JPEG/PNG metadata. `file_objects` also preserves the original sealed bytes' content hash and private object storage key.
- Dedicated `ACCOUNTANT` Campus permission `finance.admission.payment.return.evidence.submit` is live-checked on a valid verified Auth worker. An authority preflight runs before upload, then a **server-only** `BankReturnDocumentService` uses `measure_certificate`, a current Finance upload entitlement, write-once `LocalPrivateArchive` (`payments/.../SHA256`), and a read-back digest check. `db03_submit_return_bank_document` locks School → Campus → Year → Applicant → S22 Return, verifies the S22 provenance, creates the private Foundation file metadata and immutable Finance source, then an atomic command receipt/audit/outbox. Replays are single-actor/key/intent bound. The protected source is not inserted by clients.
- A distinct active `ACCOUNTANT` with separate Campus permission `finance.admission.payment.return.evidence.review`, different from the return reporter, evidence submitter and S14 original payment issuer, obtains private metadata only through `db03_bank_document_review_details`. The server `BankReturnDocumentReviewService.inspect` reads the actual private archive contents and measures the expected digest/mime/byte count. `decide` rereads before every decision and invokes the authenticated protected `db03_review_return_bank_document` with the seen SHA-256. This also verifies S24 submit receipt/audit/outbox and that an S23 independent ledger review exists, while holding School/Campus/Year/Applicant/Return/Payment locks.
- Review outcomes are `DOCUMENT_SUPPORTS_RETURN`, `DOCUMENT_DISPUTES_RETURN`, or `MORE_BANK_PROOF_REQUIRED`. All remain documentary judgments, not external bank truth. They are immutable, singly assigned per return, and generate their own one-receipt/audit/outbox proof. Raw private case/reference, reasons, private storage object keys, and document content are never included in public-facing command summaries, audit details, or event payloads. The read-only S22 funding snapshot remains **`BANK_RETURN_RECONCILIATION_REQUIRED`**.

The real Auth acceptance uploads three independent synthetic PNG documents through `LocalPrivateArchive`, independently inspects one exact SHA-256 copy, rejects a corrupted read and mismatched hash, covers unauthorized reporter/reviewer, wrong applicant, repeat/tampered submission, exact replay and changed-key review, two-backend competing review, `DOCUMENT_DISPUTES_RETURN` and `MORE_BANK_PROOF_REQUIRED`, original untouched S14/S20/S22 ledger, and revoked permissions. **Not implemented/blocked:** Authoritative bank-side settlement verification or query, partial chargeback and settlement differences, correction/resubmission beyond a single proof, Bank accountant settlement adjudication, return release/reallocation, positive Finance clearance, final Principal admission approval and Student creation. Those require separate audited authorizations and dedicated tests. PR #102 owns unrelated D1 grade and recurring/category discounts and is not touched.
