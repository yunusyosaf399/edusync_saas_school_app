The final `schoolos_evidence_writer` shared receipt override preserves all prior arms and adds only `student.roll_policy.change` `request.review` (four typed slots) and `request.apply` (two typed slots). A valid REVIEW intent contains the request UUID, APPROVE/REJECT, decimal positive expected request version as a string, and a nonblank private reason. APPLY contains the request UUID and positive expected version string. The existing JCS SHA-256, verified actor, Foundation shared advisory lock, per-key advisory lock, exact operation lookup, receipt conflict comparison, search path, owner and private ACL remain in force. Neither phase accepts a generic length or client-selected policy version.

The fixed public REVIEW and APPLY handlers now return an already completed response only after their original canonical key/hash and persisted request, decision/application, receipt, audit, transition and (for successful APPLY) historical policy/allocator/outbox evidence match. A later School policy revision does not cause an earlier successful APPLY to run again. A stale INVALIDATED APPLY returns its original terminal response without a new policy, allocator, application or event. REVIEW checks the actor's current reviewer role/grant; APPLY checks the invoker's current participant authority. Different intent with the same key conflicts. Missing or inconsistent evidence fails closed.
