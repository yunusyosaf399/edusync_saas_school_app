# Initial admission assessment source (inactive)

The published admission policy already identifies `ADMISSION_TEST` and `INTERVIEW` stages, but the current DB03 stack has no retained result source for either. This candidate adds a private assessment table for an initial examiner-selected PASSED or FAILED decision with optional paired score and maximum. The score does not automatically determine the decision. An interview or test result is not a Finance or final admission approval.

Each source is tied by real foreign keys to one application, exact School/Campus/year, latest document intake, published policy stage, assessor Principal and future atomic command receipt. A protected guard requires the application's current DRAFT version and evidence epoch, the exact required stage kind and policy lineage, and no existing result for that application/stage. The table has forced RLS, no client/worker DML or read grant, and rejects update, delete and truncate. Private reasons and scores do not enter broad outbox or reports.

The accepted product rule permits an explicit examiner PASSED/FAILED and optional score, but it has not selected who qualifies as examiner, retrospective dates, retake/correction rules or an external assessment service. This increment therefore supports **one initial retained decision only** (`revision=1`). It installs no protected examiner command, stage outcome, customer operation/permission, review bypass or Student path. A later command must obtain the exact live action/scope authority, serialize with an independently reviewed ADMIN_TEST_SKIP on the application/stage anchor, create its receipt under the protected owner before deferred constraints execute, and test both winner orders. A future retake or correction must append history under its own approved policy; no score or failed decision is overwritten.

Installation is after the current DB03 application, policy, document-intake and S21 snapshot sources. It is a non-executable `.sql.draft`; no hosted migration, deployment or merge. Disposable CI validates 14 structure/privilege properties and injected-install rollback alongside the existing Admissions/Auth regressions. This schema alone cannot qualify an application for final Principal approval. Finance-authorizer clearance and D1 Student handoff remain separate prerequisites.
