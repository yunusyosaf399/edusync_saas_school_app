## Fixed rules — not subject to discretionary selection here

1. One school = one Supabase project. PostgreSQL owns file identity, measured metadata, purpose, classification, domain relation, history and access. Provider adapters own bytes; no cross-school key, location mapping or user-selected provider. No provider registry table, provider credential/URL column, or provider-specific schema in F23.
2. `file_objects.storage_location_key` and `object_key` are immutable and unique together; server allocates file UUID/key and trusted intent **before** upload, but inserts F23 PENDING **after** measuring actual bytes. F23 content_type, byte_size, 32-byte SHA-256 and purpose_code are required measured/controlled fields. F23 lifecycle is PENDING → VALIDATED → AVAILABLE, or appropriately QUARANTINED/retained. AVAILABLE alone does not grant raw-byte access.
3. Student pictures are PRIVATE, purpose-bound to proposed registry code `STUDENT_PROFILE_PHOTO` (purpose registry handler is still disabled). V1 verified stored size **1…1,048,576 bytes inclusive**. No client MIME/digest/size, provider ETag, opaque key, uploader equality or signed URL substitutes for verification/authorization.
4. Every new upload intent **and finalization** requires authenticated current Principal, correct action/scope, Student relationship and current PRIMARY Campus, enabled module, effective nonstale signed School capability `storage.student_photo.upload` if registered/enabled, purpose registry and `file.upload`. No School Super Admin entitlement bypass. Signed snapshots have monotonic revision/freshness and durable backend high-water; no client-plan truth or unbounded outage fallback.
5. Existing authorized files survive downgrade; unavailable/staged or failed uploads stay private and unavailable. No automatic deletion of retained evidence. Secrets stay in deployment/secret manager. Private downloads require live domain reauthorization and bounded temporary mechanism, never permanent private URL or unrestricted listing.
6. `uploaded_by_principal_id` is immutable verified initiator provenance, `created_by` can be the trusted metadata executor; neither implies subject/ownership or automatic view rights. Student photo SET (#67) and live uploads remain **DENY**; Migration 10 remains nonexecutable `.sql.draft` until an independent activation decision.

## Freeze and nonactivation

This is a **decision-packet milestone**, not live implementation readiness, CI acceptance of a real adapter, provider selection, SDK installation, entitlement enablement, hosted migration, real media processing or approval of `student.photo.set`. If merged, freeze as **DOCUMENTATION-ONLY / PA-01–08 PENDING**. Real Student Photo upload and Photo SET remain disabled.

A valid staged upload remains private if the student transfers to Campus B before finalization. No snapshot, upload confirmation or prior URL can bypass the new Campus check.
