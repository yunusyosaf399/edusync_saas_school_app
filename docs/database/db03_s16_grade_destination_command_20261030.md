# DB03 S16 — protected applicant grade selection (inactive candidate)

An authorized Administrator may record the intended Class Offering for a DRAFT application. The offering resolves to a School-owned academic grade in the application's exact Campus and Academic Year. The administrator may make a later correction; each decision remains as a new immutable revision with its predecessor and reason. This does not enroll a Student or calculate a fee.

The server-only `app_private.db03_record_admission_destination` command accepts an application, expected version, D1 offering, reason and idempotency key. It derives the actor from verified Auth claims and requires an active individual Administrator with the exact `admission.destination.record` permission in the Campus. It rechecks that authority after School, Campus, Year, application and offering locks, and rejects withdrawn/forwarded drafts, closed or mismatched offerings, changed versions, and expired authentication. One transaction retains the source revision, receipt, audit and outbox. Exact replay returns the same result; a changed payload or revoked grant denies.

The operation and permission are created **only in disposable fixtures**. No parent or administrator UI, production grant, hosted migration, admission handoff or Finance price is activated. The new command is isolated from the separate one-time manual admission-fee PR stack; it neither changes those tables nor substitutes the slip's claimed amount for a charge. A later checked Finance/Admissions handoff must read the current destination revision, reject stale source revisions and independently authorize the selected fee categories.
