# D1B2 — exact physical constraint matrix (design only)

**Scope:** the 34 proposed `app_private` relations in the [D1B1R catalog](27_domain_package_01_physical_catalog.md). This is input to later SQL review, not SQL or deployment authorization. Names/types/nullability/defaults and every column are in that catalog; this document freezes integrity behavior. The [dependency graph](28_domain_package_01_exact_dependency_graph.md) gives creation order. Foundation tables, keys and roles remain frozen.

## Common enforcement contract

Every relation has `id` UUID PK and `created_by → app_private.principals(id)`; all D1 FKs, including the FKs below and `ended_by`/`archived_by`, are `ON DELETE RESTRICT ON UPDATE RESTRICT`. No D1 FK references `auth.users`. Required columns in the catalog are `NOT NULL`. The catalog's M/H/HE sets are complete: M uses `row_version bigint NOT NULL` beginning at 1 and `updated_at`; H is immutable after insert; HE is H except for a **single** protected setting of `effective_until`, `ended_at`, `ended_by` together: either at insert for an accepted initially bounded interval or later by one-way close of an initially open row. `ended_at` and `ended_by` are both NULL while open and both non-NULL after close. Neither can be cleared or revised. Archived M catalogs permit only controlled label/order/state changes and one-way archive fields; stable code and ancestry never change. All ordinary DELETE/TRUNCATE and direct authenticated DML are denied in D1B3; restricted immutable-field/defensive triggers also reject accidental privileged fixture edits. A superuser/owner capable of disabling triggers is outside this application guarantee and must be controlled operationally.

Every HE row has `effective_from < effective_until` when ended and a half-open interval `[effective_from,effective_until)`. Date and timestamp intervals use their column type; missing end means infinity. The end bound is immutable once non-NULL and must be after start; server records the verified actor and time when the bound is committed. Adjacent intervals are allowed. Overlap means `a.start < coalesce(b.end,infinity) AND b.start < coalesce(a.end,infinity)`; no `now()` partial-index predicate. The canonical as-of query requires `effective_from <= t AND (effective_until IS NULL OR t < effective_until)`, plus relationship-specific state/authorization checks. `effective_until IS NULL` alone does not mean effective today if start is future. Backdated insert/correction must pass the same locked overlap and lineage checks. A correction closes prior history and appends a successor; it never overwrites business columns. A relation with a `reason` column requires it nonblank; `roll_allocations` instead requires nonblank `correction_reason` on a manual successor. `enrollments` alone also permits the coordinated one-way `placement_state` and `end_reason` completion specified in row 15.

Cross-row and cross-table predicates below are **not CHECKs**: they run in protected commands with the parent locks in [concurrency design](31_domain_package_01_concurrency_and_locking.md), and in restricted defensive triggers for privileged fixture DML. Every trigger must acquire the same declared parent serialization anchor **before** querying other rows, or reject an unsupported direct path; a passive `SELECT` in a trigger is insufficient. Parent changes that could invalidate child facts take that same anchor and recheck dependents. Commands use `READ COMMITTED` and fresh statements after waits; uniqueness and FK failures reject rather than silently retry in SQL. Whole-command retry is permitted only through Foundation idempotency semantics. The indexed implementation is in [index review](32_domain_package_01_index_review.md).

In the matrix, `U` means a full candidate UNIQUE key, `PU` a stable-predicate partial UNIQUE index, `C` a row-local CHECK group whose clauses are all stated, `I` immutable data beyond the common H/HE rule or M ancestry, `V` the M optimistic version contract, and `L` the parent serialization anchor. `none` means no additional constraint of that class beyond the common contract. Every listed FK is in addition to universal `created_by`; nullable references are marked `?`. `self` includes an acyclic earlier-row check under the logical-parent lock; merely declaring the self FK is not a lineage proof. All referenced states are exact case-sensitive codes from the catalog; unspecified transition edges are not invented here.

**Count contract:** 34 UUID PKs; 21 selected full candidate UNIQUE keys; 3 selected partial UNIQUE indexes; 6 selected composite FKs (two on Class Offering, one each on Section Offering, Roll Allocation, Family Principal Membership and primary Family context); 20 HE temporal relations. The `C` cell in each of the 34 rows is **one exact row-local CHECK bundle** for D1C naming/implementation, so the design count is **34 CHECK bundles**, with each bundle's conjunctive clauses spelled out below. D1C may split a bundle into separately named SQL CHECKs only by documenting equivalent behavior and a changed physical count. Cross-row/parent rules are outside those bundles. Universal `row_version > 0` is included in every M row's bundle; universal HE end-marker pair and interval order are included in each HE bundle even where abbreviated in the cell.

Class Offering and Section Offering states are exactly `PLANNED`, `OPEN`, `CLOSED`, `ARCHIVED`: the first three require both archive fields NULL, and `ARCHIVED` requires both non-NULL. The approved Student status domain referred to below is exactly `ACTIVE`, `SUSPENDED`, `WITHDRAWN`, `TRANSFERRED`, `GRADUATED`, `EXPELLED`, `DECEASED`, `ALUMNI`. The D1 enrollment entry kinds are `INITIAL`, `PROMOTION`, `REPEAT`, `CLASS_CHANGE`, `SECTION_CHANGE`, `CAMPUS_TRANSFER`, `REENROLLMENT`; placement state is `ACTIVE`, `COMPLETED`, `ENDED`. The Employee state candidate frozen here is `ACTIVE`, `INACTIVE`, `ENDED`. `ARCHIVED` is a catalog lifecycle state, not a placement or employment state. No full transition edge graph beyond approved normal paths is inferred from these value domains. General text code validation means nonempty after trimming whitespace; it does not silently create a new global product vocabulary.

## Cross-row details and boundary tests

All temporal uniqueness above is a **serialized overlap rule**, not an unqualified UNIQUE on `effective_until IS NULL`. The `PU` indexes above are only for non-temporal null/receipt identity; they never substitute for historical overlap checks. Self-lineage requires referenced row in the same logical parent and a preexisting row in an acyclic chain (and strictly earlier immutable start where placement predecessor chronology requires it), forbids self-reference/cycle and reassignment; a correction of an already-corrected row is rejected unless the explicit current lineage head is superseded. For qualification/experience, the stable lineage key is immutable and equal to the predecessor's; create uses a fresh server UUID. Family relationship identity under Student+Family locks uses `(family_id,student_id,relationship_kind,adult_person_id)` when Person is present; when Person is NULL it uses normalized `display_name` and `relationship_contact` with NULL treated as a value. Exact duplicate fact intervals are rejected; different named/contact adults can coexist. Ordinary nullable UNIQUE is not trusted. Some history can legitimately overlap (different experience records, distinct family relationships, different job associations), so overlap keys are relation-specific.

Parent lifecycle changes also validate dependents under the same lock hierarchy: archiving a catalog blocks **future new use** while existing current facts remain until separately ended; ending a relationship cannot leave current child access/context without another valid relationship basis; ending Employee ACTIVE state or teacher capability cannot leave a newly valid teaching action. Where old accepted facts are historical, they remain referenced; no cascade/delete or retroactive rewriting. The Student and Employee current projections and mutable offering capacities are updated only with corresponding history in one transaction, with exactly one aggregate `row_version` increment per accepted mutable aggregate command and expected-version mismatch rejection. Appending unrelated child history does not arbitrarily bump a parent version. Details of which protected entry point may call these checks and RLS/read projection contracts belong to D1B3.

**Same-transaction completeness:** a D1C deferred constraint trigger ([PostgreSQL 17 constraint-trigger timing](https://www.postgresql.org/docs/17/sql-createtrigger.html)), run before commit while the command still holds its parent locks, rejects a newly committed Student lacking its first status transition, an accepted PRIMARY enrollment lacking pointwise exactly one effective roll allocation throughout its accepted interval, a parent capacity change lacking its matching `capacity_revisions` fact, or an over-cap accepted placement lacking its one typed override/receipt evidence. The protected command performs the same checks before returning so errors are intelligible; the deferred trigger is the last defense against a privileged fixture path that inserts only part of an aggregate. A future accepted Enrollment may not be partially visible before commit. The trigger must compare the locked aggregate and retained interval rows, not use a row-local CHECK for these facts.

Non-executable validation plan: test every FK and candidate key, each CHECK group, immutable fields, one-way close, composite wrong-Student relationship and wrong-kind FAMILY principal under privileged fixture DML; same-school/campus ancestry; adjacent/backdated/overlapping intervals; lineage mismatch; future PRIMARY overlap; class and section exact-limit/over-limit races; replayed Student ID and roll allocation; FAMILY revoke/read and child-mutation order; sensitive old snapshot retention without broad payload leakage; multiple qualifications and external jobs; teacher eligibility/end races; PRIMARY, CO_TEACHER and bounded SUBSTITUTE semantics. No executable test is added by D1B2.
