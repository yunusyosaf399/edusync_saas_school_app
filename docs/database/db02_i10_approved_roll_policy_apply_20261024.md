## Fixed approval-to-effect boundary

`app.d1_apply_student_roll_policy_change(request_id,expected_request_version,idempotency_key)` is a fixed authenticated `request.apply` entry point, distinct from I08 SUBMIT, I09 REVIEW, and I07 DIRECT. It never accepts a client-specified policy version, caller identity, old or new policy facts, effective date, allocator ID, reviewer list, or permission. It returns request UUID, request version/state and resulting policy revision UUID (or NULL on INVALIDATED). A request must have passed an independently reviewed APPROVAL policy and be in exact `APPROVED` state with the caller's expected version.

The existing original request binds the School, selected **global Foundation NULL-Campus P1 version UUID**, School-local trusted submission date, immutable expected source and new `INIT`/`REPLACE` policy facts, requester and private reason. A valid APPLY uses **today-only** School-local semantics: if the original trusted day has elapsed, it invalidates rather than silently rebasing effective date to today. INIT is permitted only if the School has no prior policy. REPLACE requires an exact current unlocked predecessor with prior effective date less than the trusted cutover; same-day repeated replacement, future committed Enrollment/Roll collisions and allocator incompatibility deny. The source preflight is the same Student-owned serializing I03 gate as DIRECT.

Before effects, transaction checks current verified INDIVIDUAL participant authority, complete School `ALL/DIRECT` requester permission and each independent reviewer’s current assigned approval role and `student.roll_policy.approve` grant. The APPLY invoker must be the original still-authorized requester or an actual previously deciding reviewer with live approval authority; no role-label, Parent/FAMILY, original request ID or historic approval is an authority shortcut. Foundation `(71001,1)` SHARED lock precedes receipt/idempotency lock; School lock precedes approval row lock and policy/allocator effect; the global P1 UUID and grants are rechecked after waits. No direct client/private-table write or generic function dispatch is exposed.

On successful APPLY the Student-owned effect closes only the exact old policy for REPLACE, inserts the next retained revision, and provisions the correct new mode-specific allocator pools **in one transaction**. Then the workflow stores one terminal `request.apply` SUCCEEDED receipt (`D1_STUDENT_ROLL_POLICY`) with exactly the approved P02 14-key result summary, one immutable `approval_applications` row bound to that receipt and request, one minimized successful private audit, exactly one `student.roll_policy_changed` outbox event (six safe keys, schema v1) and one `APPROVED → EXECUTED` transition. The operation does not renumber, reparent, or mutate any historic Student Rolls.

When a recognized deterministic stale condition occurs after an otherwise legitimate approved request is locked (P1 UUID/route changed, requester or reviewer authority revoked, old source/date or future allocation commitments no longer eligible), it instead records `APPROVED → INVALIDATED`, one terminal `request.apply` REJECTED receipt with a bounded code and one minimized audit. There is **no** policy/pool mutation, `approval_applications`, or success outbox event. Unexpected PostgreSQL/integrity/deadlock/infrastructure errors roll back and leave the approved request retryable; they are not converted into durable business rejection. Malformed stored protected requests and arbitrary participant failures are denied, not hidden.

The private reason remains only in the protected Foundation request and new retained policy revision plus the canonical digest. It is excluded from receipt summaries, broad audit/evidence, outbox, and public responses. Trigger-only schema-owner application defense checks matching request, operation, receipt, final state, exact result revision and 14-field summary. All new private helpers revoke EXECUTE from PUBLIC, anon, authenticated, and service_role; only narrow NOLOGIN executors can call them.
