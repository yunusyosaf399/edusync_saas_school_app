## Lock and security boundary

The new guards begin with Foundation authorization advisory lock `(71001,1)` in SHARED mode. School-wide roll/lineage checks use the school row before Student/Employee; Family checks use Student then Family; teaching checks use Employee then Class Offering then Section. Enrollment capacity uses Student then target Class Offering then Section. A future command that touches both source and destination must discover and prelock **all** parents in the D1B2 sorted hierarchy and revalidate after waiting. A direct privileged fixture write that conflicts or deadlocks fails as a whole transaction; it is not a substitute for the D1C1B command protocol. In particular, command-key/Foundation principal ordering, multiple source/destination sorted locks and authorization rechecks remain D1C1B work. This static review does not prove absence of hidden FK lock inversions under runtime contention.

All 34 D1 relations have both `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY` declarations. The draft's existing broad executor `USING (true)`/`WITH CHECK (true)` policies and direct internal DML grants are **provisional and unsafe as final authorization**. They are retained only in the non-executable exploratory file for D1C1B replacement. The old 87-permission/297-alternative registrar, unapproved `'bootstrap'` purpose literal, private evaluator, four partial academic checked reads and file-purpose guard likewise do not satisfy the frozen 97-permission/322-alternative, 36-command, complete checked-read and workflow/audit/ACL contracts. No authenticated base-table DML was added by D1C1A. This draft must not be renamed, applied or exposed before those later gates pass.
