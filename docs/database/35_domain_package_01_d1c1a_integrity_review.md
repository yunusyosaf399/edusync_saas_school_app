## Lock and security boundary

### Independent-review correction on `a56bc013`

The draft adds private `d1_lock_academic_path(section, room, subject)`. It discovers immutable ancestry IDs, then locks Academic Class, Campus, Academic Year, Class Offering, Section Offering, Room and Subject in that order before mutable state is tested. The effective-history trigger calls it before the Section Room or cross-Employee teacher overlap scan; the Enrollment and roll ancestry branches call it before target-state validation. Class Offering creation or transition into OPEN locks school, Academic Class, Campus and Academic Year; Section creation or transition into OPEN locks school, Academic Class, Campus, Year and parent Offering. New-use rejects archived/unusable parent states using only the frozen SETUP/ACTIVE/INACTIVE school, ACTIVE/ARCHIVED class, PLANNED/ACTIVE/ARCHIVED campus, PLANNED/ACTIVE/CLOSED/ARCHIVED year, and PLANNED/OPEN/CLOSED/ARCHIVED Offering/Section vocabularies. It does not impose a new cross-state transition graph. Section Room now checks a locked ACTIVE Room. Employee job targets lock Department then Designation; campus affiliation locks Campus. Teaching checks the locked Class/Section/Subject state and school ancestry. An end-only update of a retained assignment may still close after a parent later archives.
