## Query-path and index freeze

`PK` denotes the appropriate UUID primary key, `Uxx`/`PUxx` and `Ixx` the exact selected keys in [index review](32_domain_package_01_index_review.md). A listed index supports a candidate search; half-open interval filtering, RLS, current grant and locked cross-row validation remain required. The selected budget is **34 PK indexes, 21 full U indexes, 3 partial U indexes and 47 D1 nonunique B-tree indexes**. The separate typed-scope extension selects two target-first indexes on the existing Foundation scope table. No new index is selected here.

## Retention and as-of rule

The 34 relations divide into **11 M current/projection records, 3 H immutable events and 20 HE effective histories** as classified in the [catalog](27_domain_package_01_physical_catalog.md). M rows keep stable identity/ancestry, server-owned `row_version`/`updated_at` and controlled fields; archived catalogs retain codes, FKs and historical references. H rows (`capacity_revisions`, `student_status_transitions`, `enrollment_capacity_overrides`) are append-only evidence. HE rows are append-only except one protected, recorded setting of `effective_until`, `ended_at` and `ended_by` together; an accepted initially bounded interval records the end evidence on insert. Ordinary DELETE, TRUNCATE, retroactive overwrite and reopening are unavailable.

Student enrollment, status, restricted identity and special snapshots remain; Family relationship, membership, child access, primary context and Emergency Contact history remain; Employee restricted identity, employment, job, affiliation, qualification and experience histories remain; Section room, teaching capability/assignment, capacity and roll corrections remain. Current Student and Employee status and offering capacity are synchronized projections, not substitutes for the retained facts. Corrections append successors and preserve prior rows. No unapproved legal retention or purge duration is inferred; later policy may define controlled archival/purge without granting normal UI deletion.

Current means server evaluation date/time and `effective_from <= t AND (effective_until IS NULL OR t < effective_until)`, with the relevant state/relationship tests. Historical/as-of means the same predicate at a validated business date for an explicitly historical permission, while the acting principal, binding, complete grant, FAMILY access and current teaching eligibility remain valid **now**. Current VIEW never implies history; a revoked present grant or access cannot be revived by choosing an older date. Student status as-of uses the authoritative unsuperseded `(effective_on,sequence_number)` order; placement ancestry at a historical date uses the retained PRIMARY interval, never a current-year shortcut. A past teaching assignment is retained evidence, not current authority.

## Offline and cache contract

Only purpose-limited, field-minimized current low-sensitivity roster/reference projections may be cached, encrypted locally and invalidated when authorization or version changes. Restricted Student identity, Student Special data, Emergency Contact history and Employee restricted identity are not generally cached offline. Historic or sensitive exports/search/AI must call the same checked field class or a stricter purpose-specific surface; client hiding does not repair overbroad server output.

An offline protected-write queue stores typed intent, idempotency key and expected version, never a durable authorization decision or plaintext secrets. Reconnect obtains current identity/grants, rechecks source and destination, state and version under locks, and rejects stale version or revoked authority. Enrollment moves, status/roll corrections, Family access, Employee state and teaching assignments never silently resolve by last-write-wins. No offline Student ID, Admissions number or roll allocation occurs. This document adds no Flutter implementation.

## Cross-row and same-transaction enforcement ownership

Every D1 business mutation starts the Foundation `(71001,1)` lock **SHARED**, then the Foundation command-key lock where idempotent, then Foundation principal/workflow locks, then the [global D1 row hierarchy](31_domain_package_01_concurrency_and_locking.md): school/allocator/policy → Person/Student/Employee → Family → Academic Class/Department/Designation/Campus/Year/Offering/Section/Room/Subject → child rows, UUID-sorted within a category. Use `READ COMMITTED`, discover all source/destination parents before locking, and re-read authorization/state in a fresh statement after waits. Authority administration remains EXCLUSIVE and D1 commands never mutate Foundation grants. A direct privileged fixture path must use the same anchor/validation in a defensive trigger or fail closed.

| Invariant beyond a simple row-local key/check | D1C enforcement owner and mandatory serialization |
|---|---|
| HE half-open non-overlap, adjacent intervals, same-parent predecessor/supersedes and immutable lineage | Protected command plus immediate defensive trigger; lock logical parent before scanning all retained, future and closed intervals. FK/CHECK establishes only row shape and referenced identity. |
| School/Campus/Year/Room/Subject ancestry; archived-for-new-use state | Composite FK where frozen; otherwise locked protected command and immediate defensive check. Parent lifecycle command rechecks affected dependents. |
| Student restricted/special one effective snapshot; Employee restricted identity one; qualification/experience same-lineage intervals | Student or Employee parent lock; school lock before Employee for global lineage ownership; immediate overlap/same-parent trigger. |
| Family relationship, FAMILY membership, child access, primary context and Emergency Contact interval/basis | Student then Family and relevant Foundation Principal locks; immediate overlap/NULL-aware identity, entire-interval relationship-basis coverage and selected-context containment; relationship end closes dependents or denies. |
| Employment/job/campus/capability periods and teaching eligibility | Employee anchor, then sorted Academic parents; immediate overlap/ancestry and ACTIVE employment + capability containment check. Ending eligibility closes affected assignments atomically or denies. |
| One effective Class Teacher; Subject PRIMARY exclusivity, CO_TEACHER duplicate identity and bounded SUBSTITUTE | Section/Subject anchors in global order and immediate overlap/kind checks; SUBSTITUTE never requires an existing PRIMARY, but its own end bound is mandatory. |
| Student status chain, same-day order and current projection | Student `FOR UPDATE`; server sequence and prior-status/chronology/supersession validation in command and defensive path; unique sequence/key plus deferred initial-status/projection completeness. |
| PRIMARY Enrollment, predecessor, source/destination and future overlap | Student then all involved Campus/Year/Offerings/Sections sorted; immediate overlap/predecessor and state validation; deferred accepted-placement completeness. |
| Class and Section capacity, future commitments and override | Both Offering and Section `FOR UPDATE`; count every candidate interval segment at all existing start/end breakpoints. Command checks override permission/reason/receipt; immediate defensive validation plus deferred iff-one typed override/evidence check. |
| Student ID, roll policy/allocator, persistent or academic numeric collision | School/policy/allocator then Student/Offering/Section; U/PU keys for identity, immediate mode/namespace and collision scan, retained origin/successor check. Deferred exact roll coverage over accepted PRIMARY interval. No `MAX()+1`. |
| Capacity parent projection ↔ typed revision; Employee state ↔ employment period | Parent `FOR UPDATE`; command writes both facts atomically; deferred constraint trigger rejects an incomplete committed aggregate. |

Deferred constraint triggers run before commit while the same parent anchors remain held: a new Student must have an initial status event; every accepted PRIMARY enrollment must have pointwise exactly one effective roll allocation across its accepted interval; each parent capacity change must have its matching `capacity_revisions` fact; and an over-cap accepted placement must have exactly one matching typed override/receipt, with none for within-limit placement. Protected commands perform the same checks before returning for useful errors. Deferred validation is a last defense, not a replacement for the immediate race-safe checks. This is the selected enforcement combination, not executable SQL.

## Read, command, approval and evidence implementation boundary

The authoritative logical checked-read inventory is [D1B3B's read table](../security/09_domain_checked_reads_and_commands.md#checked-read-contract-families): academic Class, Subject, Offering and Section; current room and capacity/history; Student current ROSTER/PROFILE, restricted identity and Special current/history, current Emergency Contact and staff-only history, status/placement/roll history; Family current summary/relationship and separately permitted relationship/admin/membership history; Employee roster/profile, restricted identity, qualification, experience, employment and organization current/history; teaching assignment/capability current/history. D1C assigns fixed function names/signatures and explicit return columns to **each distinct permission/disclosure class**. A current and historical path are separate; FAMILY-safe, Student-self, Employee-self, staff direct and teaching alternatives remain exactly those in [permission catalog](../security/08_domain_permission_disclosure_catalog.md). The four academic functions in the exploratory draft are not an authoritative inventory or evidence of correctness. No `SELECT *`, base-table-shaped JSON, caller-selected table, permission or resolver.

All **36** fixed operation contracts in [D1B3B's command matrix](../security/09_domain_checked_reads_and_commands.md#protected-command-matrix) need typed `app` entry points or a reviewed fixed private workflow apply path; D1C must inventory each one against its request permission, target, source/destination check, expected version/state, P0/P1/P2 route, SHARED authorization lock, sorted aggregate locks, Foundation receipt, retained history, audit and outbox event. Every retriable command binds a canonical intent hash to `(principal,operation,idempotency_key)` and returns the same terminal result on exact replay; changed intent with the same key rejects. Domain data, terminal receipt, approved application, audit and outbox commit atomically. Broad payloads contain identifiers, action/state labels, interval/correlation only; raw identity, special, emergency, qualification/experience, arbitrary reason, object key or signed URL never enter them. No direct authenticated D1 table DML.

P0 permits fixed direct apply after current checks. P1 requires an explicit school policy choice; missing choice denies and configured approval makes direct apply deny. P2 has no direct apply route. Sensitive Student/Employee identity and special/factual corrections are P2, as is retroactive teaching correction; current/future teaching assignment is P0. At workflow application, recheck current reviewer and requester authority as required, self-approval separation, target/version/state, source and destination scope, and cross-row facts. Capacity override alone remains non-approval but requires its distinct permission, verified actor, reason, typed evidence and audit.

Migration 10 creates no SYSTEM Principal and executes no deployment catalog insert or registrar call. After Foundation bootstrap supplies **exactly one ACTIVE SYSTEM** actor with the approved bootstrap `system_purpose`, the private `schoolos_bootstrap_executor` registrar takes `(71001,1)` EXCLUSIVE and applies deterministic missing/identical/collision behavior. Permission, scope and operation vocabulary starts disabled and creates no role grant, principal assignment or user scope. The [Foundation bootstrap plan](07_foundation_bootstrap_plan.md) requires a purpose-bound bootstrap actor, but neither that plan nor executable Foundation migrations freeze its exact `system_purpose` literal or create the actor. The exploratory draft's `'bootstrap'` is not authority. The exact literal and actor UUID in the deployment manifest are a D1C2/bootstrap prerequisite; mismatch or absence fails closed. The event code manifest registers vocabulary only and activates no worker.

`student.create` is a frozen operation name whose successful effect depends on a later typed, verified, final Admissions handoff. D1 may register the vocabulary **disabled**. Without that handoff, no successful Student-create entry point may be enabled, no denial-only stub counts as implemented business behavior, and authenticated direct Student INSERT remains denied. Admissions application, reservation and allocator tables are not D1. D1C test design must prove the unavailable path fails closed until the separately designed handoff exists.

The three D1 file relationships are Student photo → `STUDENT_PROFILE_PHOTO`, Student birth certificate → `BIRTH_CERTIFICATE`, and Employee photo → `EMPLOYEE_PROFILE_PHOTO`. FK plus purpose/AVAILABLE defense is only structural. The server file service still checks current domain permission/scope, exact typed owner relationship, entitlement, file state/purpose and private temporary access. No Student/FAMILY or Employee self-upload baseline, no new generic document purpose, no worker activation.
