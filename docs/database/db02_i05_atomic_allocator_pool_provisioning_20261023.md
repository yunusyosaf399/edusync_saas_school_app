## Atomic change

`effect51_01_db02_atomic_policy_allocators.sql.draft` creates one narrow schema-owner-owned private `d1_roll_policy_provision_revision_pools(uuid,uuid,uuid)` and **replaces the existing Student-owned private I04 function with the same signature/ACL**. Its final operation INSERTs a revision, then calls the pool writer **within the same PostgreSQL transaction**, returning only after all required pools have been successfully created. Any exception during pool allocation rolls back the new revision **and** its preceding source closure. No new public/app/Workflow EXECUTE edge, direct Student/anon/authenticated pool table INSERT, or policy/event enablement.

The pool writer is private SECURITY DEFINER with fixed search path. It verifies a current verified individual Principal matching the newly created revision's `created_by`, matching School and School-local today, a **new row created in the current transaction**, approved immutable mode, and no already provisioned target rows. It is callable only from the NOLOGIN Student executor's private composition edge (with an explicit, purpose-limited EXECUTE grant). **A separately credentialed non-author SQL/security reviewer must assess this schema-owner privilege boundary before activation**; owner/ChatGPT self-review and passing CI are not the independent security approval.

**Persistent policy:** exactly one `(new_revision,NULL)` allocator. Initial `next_value` is the maximum of (a) the new minimum, (b) all retained persistent School-wide prior-pool `next_value` reservations and (c) one more than every historically assigned persistent Roll number for the same School, regardless of the prior allocation's end/supersession. If high-water arithmetic or `bigint` headroom is exhausted, fail closed; never wrap, reuse old student numbers, or silently correct history. No source counters/old Rolls are changed.

**Academic policy:** one `(new_revision,class_offering_id)` pool for every existing Class Offering in the School that has state PLANNED, OPEN or CLOSED and usable School/Class/Campus/Academic Year ancestry. State ARCHIVED is excluded. OPEN with invalid ancestry fails closed, rather than silently skipping. No capacity requirement (even zero capacity), Section count requirement (even zero Sections), or campus-only policy selection. Fresh per-Offering counters equal the new revision's `start_value`. Candidate lock ordering is School → existing revision/pool locks (I03) → sorted Campus rows → sorted Year rows → sorted Class rows → sorted Offering rows, with parent state re-read at the locked snapshot. This narrow projection is implemented inside the fixed-purpose writer, avoiding new broad Academic-table grants or cross-owner SQL edits. **Academic owner approval of the later Offering-create/reopen provisioning hook remains OPEN under G02**.

All valid actor/auth/idempotency/School/policy-source/date/future-commitment preflight checks from I01–I04 are retained; no policy cutover without matching pool rows in the same transaction. This does not register a result receipt, audit event, outbox event, or public/direct/approval command.
