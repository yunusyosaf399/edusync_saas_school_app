## 3. Receipt and replay authorization threat audit

| Threat or attempted misuse | What must be proven at implementation/runtime |
|---|---|
| **Forged successful receipt** with arbitrary corrected Roll UUID | Exact fixed `D1_STUDENT_ROLL_CORRECT` result ref/new Roll UUID + immutable R0/R1 pair/effective boundary/actual corrected number/source Enrollment/source policy + one matching authenticated receipt hash and writer provenance. No second success receipt for same R1. |
| **Misbound reviewed APPLY** matching a legitimate Roll but wrong approved value | `approval_requests.old_snapshot` Student/Enrollment/Section/source Roll/policy/old number + `requested_payload.proposed_numeric_value` + restricted reason match receipt/successor exactly; one `approval_applications` request+receipt+R1 link; request has approved independent review and exact policy version. |
| **Historic receipt revalidation erroneously requiring Roll still OPEN** | Return immutable original R0→R1 after later R1→R2, MOVE or END; never demand current source Enrollment ACTIVE, successor open or Student original row_version on *terminal same-key replay*. New mutations still demand current active source. |
| **Stale reviewer or requester grant** | At approved APPLY, refresh both requester's and every reviewer grant/step and policy UUID after locks. Authorized actor with business-stale request can INVALIDATE; unauthorized actor cannot. Unexpected constraint/deadlock exception rolls back without terminal rejection receipt. |
| **Former Campus history leakage** | Person who participated in a correction but lost current matching staff authority does not automatically regain private old/new number or request data. Checked historical Roll read verifies current `student.roll_history.view` scope and request participation; existing FAMILY/OWN grant is not staff correction authority. A retained END Enrollment is not by itself proof of no current School-scoped history authority. |
| **Reason leakage** | Exact stored reason validated/hashed but not copied into broad audit/outbox/request read. SQLSTATE and logs must not expose raw reason, old/new numeric, request JSON or actor secrets to unauthorized callers. |
| **Idempotency key abuse** | Receipt key bound to verified individual Principal+operation; canonical intent with exact approved typed values. Same key with modified proposed numeric, source id, expected version or reason rejects; next-day same key does not hash a volatile current date and cannot create a second correction. |
| **Cross-mode/numeric overflow** | Full School history for PS reserved to owner even after supersession and new revisions. Academic revision+Offering overlap. High-water updates are in same transaction and no manual overflow/negative/same-value gets accepted. |
