## What complete means

A requirements document, table catalog, SQL draft, applied migration, and verified business workflow are different deliverables. A package is complete only when its requirements trace to an exact physical catalog, dependencies, migrations, constraints/indexes, scoped reads and protected commands, history/workflow/audit contracts, and passing positive, negative, replay, concurrency, install and upgrade tests. UI code is not part of this database gate.

Preserve one school per Supabase project, campus scoping, Foundation identity, separate family credentials, immutable finance/result/attendance history, controlled file purposes, server-only secrets and domain authorization. Reuse Foundation rather than creating parallel identity, approval, receipt, audit or event engines. Previously validated Foundation migration bytes and tests remain frozen.

## Package deliverables and release gates

For each matrix row, complete: requirement references and scope; all entities with exact columns/types/nullability/defaults; PK/unique/FK and ancestry proofs; lifecycle/history/retention; constraints and indexes with query patterns; role/action/scope/assignment/state matrix; protected read/command signatures; workflow/audit/outbox/file contracts; offline/replay rules; migration dependency/upgrade plan; happy, negative, boundary, concurrency and reconciliation tests.

Work order: finish D1 domain tests and populated upgrade validation; Admissions/creation and curriculum; calendar/timetable and attendance; learning/exams/results; Finance; HR/payroll/leave; Library/Transport/Hostel/Medical; remaining platform/control-plane contracts and future extensions; whole-school install/upgrade/restore and workflow verification. Designs may progress across dependent packages before their SQL is executable; do not activate a package whose prerequisites are incomplete.

Final database gate requires every applicable CORE/OPTIONAL row and the defined future database designs to have recorded status/evidence, all executable packages to install and upgrade cleanly, every domain to pass authorization/history/concurrency acceptance tests, and end-to-end admissions/promotion/attendance/payment/result/payroll workflows to reconcile. Unresolved decisions remain visible blockers for their affected packages. Passing a source guard cannot close this gate.
