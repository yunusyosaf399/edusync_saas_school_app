# DB08 F5 — class and Student full-price fee selection candidate

F5 connects a published Finance rule to a real D1 Class Offering. A retained applicability covers a future effective date interval for either every Student in that offering (class default) or one named Student (explicit full-price exception). An authorized Finance configurator binds the rule; the same current `finance.fee.configure` permission and School-wide `ALL/DIRECT` scope used for F2 are required. This is a pricing assignment, not a discount or adjustment. The rule's published gross amount is used without subtraction, proration or rounding.

For a requested category and frequency, an active Student-specific applicability takes precedence over the class default. Multiple matches at the chosen precedence fail closed. The period must fit one current active PRIMARY Enrollment in an OPEN Section and Class Offering in the same School, Campus and Academic Year; the selected published price revision must cover the whole period. The selected Student, Enrollment, Class Offering, applicability and resulting obligation are linked by an immutable Finance source row. Moving classes later does not rewrite an old charge. The Finance command retains the F2 exact receipt, audit and outbox evidence and checks current authorization after locks. The class and Student bindings have their own exact receipt/audit/outbox. A second binding at the same target, category and frequency cannot overlap its valid dates.

Once installed, the former direct `app.assess_finance_fee` is no longer executable by `authenticated`. The new `app.assess_selected_finance_fee` resolves the D1 source under a no-login command owner and invokes the retained full-price assessment in the same transaction. Anonymous and service roles have no client Finance RPC or private D1/Finance table access. This F5 proposal is inactive; the production API cutover would require its separate release gate.

The Student and Enrollment must already exist. This slice does not resolve an applicant's prospective class before final admission, collect money, issue Finance admission clearance, create a Student, or choose every optional fee automatically. The pre-Student admission fee/zero-obligation determination and the School-led Finance clearance are separate next contracts. Student-specific **full gross price** is distinct from a discount. Discount eligibility, amount, precedence against prices, approval thresholds and adjustment history are left for the owner's next decision.

The owner subsequently chose a Student discount with independent fixed-amount/percentage and recurring-monthly-tuition/specific-charge options. The [F6 design gate](db08_f6_student_discount_choice_20261027.md) records that choice and its unresolved arithmetic/approval details. F5 SQL continues to assess only the gross fee.

The Finance command takes the exclusive shared-transaction fence at `(71001,1)`; D1 Student and Enrollment mutations take its shared mode, so the checked placement cannot change midway through fee selection. Disposable acceptance resets the local stack after the accepted DB08 F1–F4 regression, applies the pinned D1 draft, rehearses an injected F5 install failure and rollback, and tests class defaults, Student exception, enrollment/category denial, overlap, retained source, exact replay and raw Person-assessment client denial. A separate transaction uses a real local Auth token verified by the service adapter for full-price binding and assessment, then rolls back. It does not install any draft into a hosted School project. Exact run/head results are recorded in draft PR #102.

Example: Grade 5 tuition is 100.00. One Student has an explicitly configured full price of 150.00. Their November charge is 150.00, and another Grade 5 Student's is 100.00; both retain the class placement, rule and price used. No discount is applied.
