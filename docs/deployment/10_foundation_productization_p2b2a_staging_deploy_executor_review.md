## Executor boundary

A later operator `preflight --source-sha <exact 40-character HEAD>` may perform read-only Management GET, read-only PostgreSQL queries, a migration dry-run, lint and hosted configuration checks. `deploy` requires `--apply`, exact `--confirm-environment staging`, pinned `--confirm-project-ref`, pinned `--confirm-project-name`, and `--confirm-source-sha` equal to exact clean HEAD. No arbitrary project-ref, production mode, force mode, wildcard, or executor `--yes` exists. After all exact gates and the dry-run pass, the one-shot internal child-process command is `db push --yes` so deployment is noninteractive; a failed push is never retried, and already-exact STATE B makes zero pushes. No project deletion helper or project DELETE path is imported or reachable. Failure means stop, preserve staging, and report a safe code.

Only a future explicitly authorized remote mode reads `SUPABASE_ACCESS_TOKEN` and `SCHOOL_OS_STAGING_DB_PASSWORD` from its process environment. Neither is accepted as an argument, manifest value, or credential-bearing URI. The read-only probe verifies PostgreSQL version, database and user with the P1R diagnostic classifications and bounded retry only for the initial probe. Raw remote response bodies, credentials, passwords and JWTs are excluded from errors and evidence.

Before any remote mutation, the executor requires full exact source SHA, clean worktree, frozen-source/local-config guard, no future migration, nine frozen migrations and nine frozen DB tests, CLI version, independent exact-ref detail/list identity match, project/database/Auth/REST health, valid reviewed route and probe.
