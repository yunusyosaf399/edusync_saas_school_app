# Domain package 01 — deferred scope-resolver contracts

**Status:** D1A resolver contract updated by [approved D1B0 decisions](../decisions/DOMAIN_PACKAGE_01_APPROVED_DECISIONS.md); physical design may proceed, but no SQL functions, registered scope grants, policy changes or activation are authorized. A domain relationship alone never grants an action. `app_private` stays unexposed.

## Common resolver rule

Inputs are the verified caller principal, requested action/permission, stored target identity (not client-asserted campus), requested business/effective time, and operation time. The evaluator must establish a single school's ancestry through stored Foundation campus/year and D1 offerings; class, section and subject identifiers cannot be mixed across campuses or years. It then checks an active complete grant compatible with the requested scope and the relevant effective relationship. A missing parent, unproven target, ambiguous active relationship, inactive actor, expired assignment, contradictory time, archived current target, absent resolver or resolution error returns **DENY**, never ALL. Historical reads use an explicit historical permission and scoped relation valid in the historical context as policy permits; a past assignment does not give perpetual present access. Writes check current authority and, for moves, both source and destination scopes. Auth/session context and field classification remain independent gates.

## Caller and security contract

Only reviewed checked read interfaces and protected domain commands invoke resolvers; clients cannot call a privileged resolver to enumerate IDs or claim an actor/campus. Student RLS selects **which student**, while ROSTER, PROFILE, RESTRICTED IDENTITY and SENSITIVE/SPECIAL checked projections select **which fields**; neither a role label nor FAMILY membership exposes all fields. Emergency Contact is not a portal-access resolver. Department, Designation and Employee Campus Affiliation are organizational facts, not grants. A service/worker principal is purpose-bound, not an arbitrary impersonation route. Cached JWT role or UI-selected dashboard is not authority. Assignment creation/end, family portal linkage and enrollment movement are protected commands with independent admin grants, expected versions, audit and review where policy requires. Resolver evaluation must not recursively bypass RLS or expose raw grant/evidence tables; function owner, search path, EXECUTE and lock order need D1B/C review against [Foundation execution security](04_foundation_execution_security.md).

Negative-test backlog: unrelated-child FAMILY read; emergency contact or historical guardian improperly gaining portal access; employee campus affiliation/designation treated as permission; ROSTER view leaking restricted identity/special fields; forged/current versus historical campus/year; expired substitute or teacher assignment; duplicate active PRIMARY subject teacher; teacher self-assignment; parent/employee Person overlap; direct DML; archived structure reuse; concurrent class or section capacity claim; duplicate active PRIMARY placement; stale offline replay; resolver exception interpreted as ALL; read permission used to mutate attendance/marks; cross-campus move checking only destination; object key/search/export/AI bypass of child/field scope. Each requires real non-owner/RLS tests before activation.
