# D1B3A — domain authorization resolver matrix

**Design only.** Use with the [additive scope storage contract](06_domain_authorization_scope_extension.md); no resolver or D1 SQL is installed. D1B3B chooses exact permission codes, supported scope alternatives, checked read/command surfaces and disclosure rules. Every row below additionally requires a verified principal, one complete live same-chain grant, an enabled permission-scope contract that supports that row's scope/resolver for the fixed operation, target state, field class and applicable workflow. An alternative scope never bypasses a mandatory contextual assignment or a family-safe classification.

| Context | Physical kind / expected resolver key | Direct target in scope row | Authoritative stored domain path | Operation/effective-time rule | Disclosure and fail-closed boundary |
|---|---|---|---|---|---|
| School | ALL / DIRECT | all four NULL | One school Supabase project; requested target still loaded from stored row | Current grant at operation time; only permission-approved historical mode may use old business date | No automatic sensitive fields, assignment, workflow or another school; unknown target denies. |

For a Class-target operation, a complete grant may evaluate ALL, matching CAMPUS or matching CLASS only when the permission contract lists that alternative. Section-target operations may additionally allow matching SECTION, reviewed ASSIGNED or Student OWN/FAMILY paths as appropriate; no universal parent-scope inheritance is assumed. Subject-target operations may include exact SUBJECT and reviewed Section/Class/Campus/ALL alternatives, with any operation-required teaching assignment checked independently. D1B3B must register each permission's allowed alternatives; unregistered combinations deny.

**Current versus historical:** Current permission never automatically grants historical read. A historical read needs a present live grant for an explicitly approved historical read permission, a target/placement/assignment relationship valid at the requested historical date where that operation requires it, and a field-class gate. A revoked grant, inactive account or ended employment cannot be revived by passing an earlier date. Caller-provided dates are validated business inputs, not authority. For writes and approvals, check current authority and source plus destination ancestry on moves, and recheck after waits under the [D1B2 lock contract](../database/31_domain_package_01_concurrency_and_locking.md).

**Reader inputs:** `schoolos_authz_reader` already reads Foundation principal/binding/role/permission/assignment/grant/contract/scope inputs. Future column-limited SELECT and nonrecursive role-specific RLS inputs should include `academic_classes` (identity/state only when class eligibility is checked), `class_offerings` (IDs, school/class/campus/year, state), `section_offerings` (IDs, parent/campus, state), `subjects` (ID, school, state), `students` (ID, Person, current state), `enrollments` (Student, Section, PRIMARY kind/state, interval), `families` (ID, state), `family_principal_memberships` and `family_student_access` (keys, intervals), `family_relationships` (keys, interval only when verifying approved basis), `employees` (ID, Person, current state), `employment_periods`, `employee_campus_affiliations` (Employee, Campus, interval for target CAMPUS resolution only), `teacher_capabilities`, `class_teacher_assignments` and `subject_teacher_assignments` (keys, kinds, intervals). Do **not** grant this role SELECT on Student special/identity values, Employee National/CNIC/qualification text, broad audit/outbox payloads, or arbitrary file metadata. An RLS policy on these input relations must not call a D1 evaluator, else recursion can occur. Checked reads/commands are the only external use of evaluator results; authenticated gets no direct private evaluator EXECUTE or input-table SELECT.

## Required future non-owner denial matrix

The later executable suite must test both allowed exact paths and denial for: CLASS another year; CLASS another campus; SECTION forged parent/campus; SECTION-to-CLASS without allowed parent alternative; SUBJECT same catalog Subject in another Section; SUBJECT mismatched school; ASSIGNED after assignment end; SUBSTITUTE outside interval; inactive Employee; ended Teacher capability; FAMILY principal using Student/Employee self; INDIVIDUAL borrowing FAMILY child; Emergency Contact/adult Person as access; Department/Designation, qualification and Employee campus affiliation as grants; missing/disabled/unknown resolver as ALL; historical date reviving revoked authority; direct authenticated internal helper EXECUTE; direct authenticated private input SELECT; administrator without EXCLUSIVE `(71001,1)` authority lock; D1 domain command changing Foundation grant rows. Also rerun Foundation ALL/CAMPUS/OWN SELF_PRINCIPAL, mixed-role and FAMILY tests. No executable test is created now.

The D1B3B product/disclosure questions are resolved by [the approved decisions](../decisions/DOMAIN_PACKAGE_01_D1B3B_APPROVED_DECISIONS.md): current FAMILY Emergency Contact read is separately family-safe; Student self Restricted Identity denies; Teacher PROFILE is class-teacher-only when separately granted; and history is a separate permission family with no default grants. Exact support sets are in [the D1B3B permission catalog](08_domain_permission_disclosure_catalog.md). Employee Campus Affiliation is now listed only as a target-to-CAMPUS resolver input; it remains non-authorizing by itself.
