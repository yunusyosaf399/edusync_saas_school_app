## D1B2R correction verification

The corrected design retains exactly 34 relations and introduces none. Offering state checks now match the D1B1R catalog without altering Student or Employee ACTIVE states. The command matrix explicitly places Campus before Year, Class Offering before Section Offering, Room after Section Offering, and Subject last; required FK/ancestry locks are precollected, sorted and reacquired from the beginning if the set changes. No declared command takes a lower-ranked D1 lock after a higher-ranked one. The Student status stream has a deterministic server sequence, one new full UNIQUE key and a revised I18; the selected nonunique index count remains 47. No SQL, extension, migration or executable database test was introduced.

## Product decisions and boundaries

There are **zero product-owner questions required to complete D1B2**. No complete Student/Employee state-transition edge matrix is invented: D1B3 may expose only the explicitly approved transitions and must obtain a separate product decision before activating another edge. No single-primary-job restriction or requirement that SUBSTITUTE overlap an existing PRIMARY is fabricated. A substitute may be represented without that structural dependence, but operational permission still requires the complete grant and effective assignment. Later Admissions, curriculum, HR compensation/contracts/leave, attendance, medical, worker and UI packages remain deferred.
